AI Career Prediction and Job Portal System

A complete guide for anyone reviewing, examining or extending this project. It covers what the system does, how every algorithm works, where each piece lives in the codebase, and the questions people usually ask about it.

React 19 + Vite + Tailwind Laravel 12 + JWT + SQLite FastAPI + scikit-learn + spaCy Repo: github.com/Bisu56/ai-career-system

What the system does

One platform, two jobs: help people understand where their resume points them, and help employers hire from that pool.

Resume intelligence

A job seeker uploads a PDF. The system pulls out the text, finds skills, predicts a career with machine learning, scores the resume against that career, lists missing skills, and recommends courses, interview questions and job titles.

Job portal

Employers post jobs. Job seekers search, save and apply. Each application carries the applicant's latest resume, and the employer sees applicants ranked by an AI match score.

Moderation

Admins approve employer accounts, approve or reject every employer job before seekers can see it, manage users, and pull in remote jobs from public job boards.

Architecture

Three independent services. The browser only ever talks to Laravel; Laravel is the only thing that talks to the AI service.

Why three services instead of one?

Python has the best machine learning and NLP libraries (scikit-learn, spaCy). PHP and Laravel give fast, well-tested authentication, validation, database migrations and routing. Keeping the AI in its own service means the model can be retrained, scaled or replaced without touching the web app, and the web app keeps working (with fallbacks) if the AI service is down.

Key flows

Resume upload and analysis

  1. The seeker picks a PDF (max 2 MB, checked in the browser and again on the server) and can paste a job description.
  2. POST /api/upload-resume: Laravel validates it, stores the file under storage/app/private/resumes, and runs pdftotext to get plain text.
  3. Laravel sends the text (and the optional job description) to the AI service's POST /analyze.
  4. The AI service extracts skills and entities, predicts the career, calculates the resume score, missing skills, job match percentage and recommendations (details in Algorithms).
  5. Laravel saves the summary columns plus the full JSON report in the resumes table, then returns it to the browser.
  6. If the AI service is unreachable, Laravel still saves the upload with safe defaults (score 0, career "Unknown") instead of failing.

Hiring flow

Job statuses: applied → shortlisted → interview → selected or rejected. The seeker can withdraw any time before a final decision. An employer cannot change a withdrawn application.

Algorithms

Everything the AI service does, in the order it happens. Code: backend/ai-service/main.py unless noted.

1. PDF to text

Laravel uses spatie/pdf-to-text, which runs poppler's pdftotext command. That works for text-based PDFs. A scanned image PDF returns little or no text (there is no OCR). When a resume has fewer than 25 words and no recognised skills, the AI service returns insufficient_text: true and no career at all, instead of guessing, and the page asks for a text-based PDF. Resume text is capped at 200,000 characters so a huge file cannot stall the service.

2. Skill extraction (dictionary matching)

extract_skills() lowercases the resume and checks it against a curated list of about 110 skills in skills_db.py, plus aliases (for example nodejs counts as node.js, k8s as kubernetes). Each term is matched with a regex that requires the characters on either side not to be letters or digits:

(?<![a-z0-9]) + escaped_skill + (?![a-z0-9])

That is stricter than a plain word boundary and correctly handles skills with symbols such as c++, c#, .net and ci/cd, while stopping java from matching inside javascript.

3. Named entities (spaCy)

nlp_resume_parser.py runs spaCy's en_core_web_sm model to pick out a PERSON (the candidate's name) and ORG entities, and a regex for email addresses. This is shown as extra context and is not used for scoring.

4. Career prediction, two ways

Rule-based

Each of the 25 careers has 6 core skills in CAREER_MAPPING. The career whose core skills overlap most with the extracted skills wins. Simple and fully explainable.

Machine learning

A TF-IDF vectorizer (unigrams and bigrams, sublinear term frequency) turns text into a weighted word vector, and a multinomial Logistic Regression classifier predicts the career. It returns a probability for each class; the top three are shown with confidence percentages.

tfidf(t, d) = (1 + log tf(t, d)) × log((1 + N) / (1 + df(t))) + 1, then L2-normalised
P(career = k | x) = softmax(W·x + b)k

The input to the classifier is the resume text plus the extracted skill names, so the recognised skills get a small extra weight. The ML prediction is the career: it drives the resume score, the skill gaps, the courses and the interview questions, and it is what gets saved. Using one career for everything keeps the report consistent (an earlier version scored against the rule-based career while recommending courses for the ML one). The rule-based career is still shown next to it as a simple, explainable cross-check.

Training data (train_model.py), 13,587 rows in total:

  • 13,012 real, anonymised CVs from the Djinni Recruitment Dataset (MIT licence; Drushchak and Romanyshyn, UNLP at LREC-COLING 2024). Each CV's role label is mapped to one of our careers by dataset/build_djinni.py, using the candidate's primary keyword and job title (for example a JavaScript CV titled "Full Stack Developer" becomes Full Stack Developer). At most 700 CVs are kept per career so large roles do not drown out small ones.
  • 375 curated rows (dataset/careers_curated.csv) built from each career's core skills, which cover the three careers Djinni has no CVs for (Financial Analyst, Research Analyst, AI Researcher).
  • 200 rows from the original Kaggle career dataset (dataset/careers.csv).

The classifier uses word and two-word TF-IDF features (English stop words removed, up to 40,000 features) and a class-balanced Logistic Regression (C = 10), so rare careers are not ignored.

EvaluationResult

How the number was measured: 20% of the real CVs were set aside before training and only used for testing, so 86.1% is an honest estimate on real resumes. train_model.py prints this score every time it runs. The CVs come from an IT job platform, so accuracy is highest for tech roles; non-tech careers such as Financial Analyst rely on the smaller curated data. Most remaining mistakes are between genuinely close roles (Software Developer vs Software Engineer, Frontend vs Full Stack).

5. Resume score and skill gaps

resume_score = |extracted_skills ∩ core_skills(predicted_career)| / |core_skills(predicted_career)| × 100
missing_skills = core_skills(predicted_career) − extracted_skills

So a backend resume with 5 of the 6 backend core skills scores 83.33%. The score measures coverage of a career's core skills, not writing quality.

6. Job description match (optional)

If the seeker pastes a job description, a fresh TF-IDF vectorizer (English stop words removed) is fitted on the two texts and the cosine similarity between them is reported.

match_percentage = cos(vresume, vjob) × 100 = (vr·vj) / (|vr| |vj|) × 100

7. Recommendations

  • Courses and interview questions: looked up by predicted career in courses_db.py and interview_questions.py. All 25 careers have 5 courses and 8 questions.
  • Suggested job titles: 26 reference roles in skills_db.JOBS, ranked by how many of their skills the resume has.
  • Resume suggestions: resume_suggestions.py gives a verdict band (below 50, below 75, 75 and over), names the missing skills, and adds standard resume advice.
  • Real open jobs (Laravel, JobController@recommended): every approved, active job is scored against the seeker's latest resume and the top 10 are returned.
if the job lists required skills: score = |required ∩ resume_skills| / |required| × 100
else (external jobs): score = min(100, 25 × number of resume skills found in title + description)
+20 bonus (capped at 100) when the predicted career appears in the job title

8. Applicant ranking for employers

Each application is scored right after the seeker submits it (the work runs after the response is sent, so applying stays fast). The scoring lives in app/Services/ApplicantScorer.php. Laravel sends the AI service's POST /match the applicant's skills (from the resume attached to the application), the job's required skills, and two texts: applicant (name, skills, cover letter) and job (title, description, skills, level, education).

skill_ratio = |required ∩ applicant| / |required|
text_similarity = TF-IDF cosine(applicant_text, job_text)
score = (0.70 × skill_ratio + 0.30 × text_similarity) × 100
(if the job has no required skills: score = text_similarity × 100)

Hard skills dominate at 70% because they are the most objective signal. The 30% text part rewards relevant wording and a tailored cover letter. If the AI service is down, Laravel falls back to the plain skill overlap percentage so ranking still works. Applicants are sorted by score, ties share a rank, and the earlier application wins a tie in the list order. Employers can click "Re-score All" after editing a job.

9. External job feed

job_sources.py reads the WeWorkRemotely and RemoteOK RSS feeds (and the Adzuna API if ADZUNA_APP_ID and ADZUNA_APP_KEY are set for the AI service), filters by keyword and removes duplicates by an external_id built from the source's ID. The admin triggers it from /admin/feed; Laravel upserts the jobs as approved listings and never overwrites an employer's own job even if the IDs collide. External jobs cannot be applied to inside the portal; the seeker is sent to the original posting.

Security and business rules

Authentication

  • Stateless JWT (tymon/jwt-auth), sent as Authorization: Bearer.
  • Passwords hashed with bcrypt; minimum 8 characters with an uppercase letter and a number.
  • A 401 anywhere clears the token and sends the browser to /login.
  • Deactivated accounts cannot log in (403) and their existing tokens stop working immediately (checked in the auth middleware on every request).
  • Tokens last 60 minutes; the frontend silently refreshes them through POST /api/refresh, and sends people back to the page they were on after logging in again.

Authorisation

  • Every admin endpoint checks is_admin on the server; the React route guards are only for navigation.
  • Employers only see and change their own jobs and applicants (queries are scoped to employer_id).
  • Seekers only see their own resumes and applications.
  • Admins cannot demote, deactivate or delete themselves.

Job visibility

  • Seekers only see jobs that are active and approved.
  • Employer jobs start pending; editing the content of an approved job sends it back to pending.
  • Hidden jobs return 404 to seekers unless they already applied to or saved them.

Applying

  • Only job seekers can apply (employers and admins get 403).
  • Only approved, active, employer-posted jobs before their deadline accept applications.
  • One application per job per seeker.
  • Resume uploads: PDF only, 2 MB max, rate limited to 10 per minute per user.
  • Login and registration are rate limited (10 per minute per IP, 5 per minute per email).
  • Emails are stored in lower case, so one address can't create two accounts.

Limitations and future work

Known limitations

  • Skill extraction is dictionary based, so skills not in the list are missed and context ("no experience with Java") is ignored.
  • The career model is strongest on tech roles because most real training CVs come from an IT job platform.
  • Scanned image PDFs are not read (no OCR).
  • No email notifications for status changes or approvals.
  • SQLite suits a single server; a busy deployment should use MySQL or PostgreSQL.
  • External job listings have no descriptions, so their recommendation scores rely on the title only.

Good next steps

  • Collect real, labelled resumes and retrain; try sentence embeddings for matching.
  • Use spaCy's EntityRuler or a trained NER model for skills.
  • Email or in-app notifications.
  • OCR for scanned PDFs (Tesseract).
  • Rejection reasons for employers and jobs.
  • Queue AI scoring in the background for jobs with many applicants.

Questions and answers

The questions examiners, reviewers, clients and new developers tend to ask. Use the search box to filter.

General
What problem does this project solve?

Job seekers often don't know which roles fit their skills or what to learn next, and employers spend time reading resumes that don't match. The system analyses a resume automatically to give career direction and skill gaps, then connects seekers and employers through a moderated job portal where applicants are ranked by fit.

Who are the users?

Three roles: job seekers, employers and admins. See the Roles section for what each can do.

Is the AI making hiring decisions?

No. The AI only produces a score and a skill breakdown to help sort applicants. The employer reads the resume and cover letter and makes every status change by hand.

Where is the source code?

On GitHub at github.com/Bisu56/ai-career-system. The main branch has everything. The Codebase section above maps each folder and file.

What technologies were used and why?

React for a fast, component-based interface; Laravel for secure auth, validation, routing and migrations; FastAPI with scikit-learn and spaCy because Python has the best ML and NLP tooling; SQLite so the project runs with zero database setup. Tailwind keeps styling consistent, Recharts draws the charts.

AI and algorithms
How does the career prediction work?

The resume text is converted to a TF-IDF vector (how important each word and two-word phrase is), and a Logistic Regression classifier trained on labelled examples outputs a probability for each of 25 careers. The highest is the prediction, and the top three are shown with their confidence.

Why Logistic Regression and not deep learning?

It was measured, not assumed: on the same held-out real CVs, a linear SVM scored within 0.1 points of it (86.2% vs 86.1%), and adding character n-grams did not help. Logistic Regression on TF-IDF trains in seconds, runs on any laptop without a GPU, gives probabilities for the top-3 display, and its weights can be inspected to see which words push towards which career. A transformer model might add a few points but would need a GPU and much more memory for a small gain.

How accurate is the model?

86.1% accuracy (macro F1 0.83) on 2,603 real CVs that were held out from training, up from 55% for the first version. All 5 sample resumes are classified correctly. It is most reliable for tech roles, and it refuses to guess when a resume has too little text.

What is TF-IDF?

Term Frequency times Inverse Document Frequency. A word scores high when it appears often in this document but rarely across all documents, so "laravel" matters more than "team". Each document becomes a vector of these weights.

What is cosine similarity and where is it used?

It measures the angle between two vectors: 1 means the same direction (very similar text), 0 means nothing in common. It is used for the resume versus job description match percentage and for the text part of the applicant ranking score.

Why are there two career predictions (ML and rule-based)?

They answer different questions. The ML model reads the whole resume and gives the best overall fit. The rule-based method compares against a fixed list of required skills per career, which is what you need to calculate a resume score and list missing skills. Showing both also makes the result easier to explain and sanity check.

How is the resume score calculated?

The share of the predicted career's six core skills found in the resume, times 100. Five of six gives 83.33%.

How are applicants ranked?

70% skill overlap with the job's required skills plus 30% TF-IDF cosine similarity between the applicant's profile text and the job text. Scores are calculated automatically when someone applies and can be refreshed with "Re-score All".

Why 70/30 weighting?

Listed skills are the most objective evidence of fit, so they dominate. The text similarity catches relevant experience and a tailored cover letter that the fixed skill list would miss. It is a design choice, not a learned weight; with real hiring outcomes it could be tuned.

What happens if the AI service is down?

Uploads still save with default values, and applicant ranking falls back to a pure skill overlap percentage calculated in PHP. The admin feed refresh reports a clear 502 error.

How are skills extracted from a resume?

By matching the text against a list of about 110 known skills and their aliases, with a regex that respects symbols like C++ and C#. spaCy is used separately for names and organisations.

What happens if an employer is rejected or deactivated after posting jobs?

Their jobs disappear from search straight away, nobody can apply to them, and the employer loses access to applicants and resumes. This is enforced in one database scope (visibleToSeekers), so every page follows the same rule.

Where does the training data come from and can it be rebuilt?

From the public Djinni Recruitment Dataset on Hugging Face (MIT licence). backend/ai-service/dataset/build_djinni.py documents the download, maps each CV to a career and writes careers_djinni.csv. Running it and then train_model.py reproduces the model and prints the held-out score.

Can the model be retrained?

Yes. Add rows to the CSV files in backend/ai-service/dataset and run python train_model.py, then restart the AI service. It writes new model.pkl and vectorizer.pkl files.

Where do the course and interview recommendations come from?

Curated lists per career in courses_db.py and interview_questions.py. They are chosen by the predicted career. They are not generated live by an AI model.

Is any external AI API like ChatGPT used?

No. All models run locally in the AI service. The only external calls are to public job boards when an admin refreshes the feed.

Could the model be biased?

It only looks at resume text and skills, not names, gender or age, and spaCy's name extraction is not used for scoring. Bias can still come from the training labels and from wording differences, so the score is advisory and a human always decides.

Job portal
Why must an admin approve employers and jobs?

To stop fake companies and scam postings reaching job seekers. Employers can set up a profile while pending, but cannot post until approved, and every job is reviewed before it goes live.

What happens when an employer edits a live job?

If they change the title, description, required skills, level or education, the job goes back to pending review. Changing only the salary, location, type, deadline or open/closed status does not.

Can seekers apply to external jobs?

No. Jobs imported from WeWorkRemotely, RemoteOK or Adzuna link to the original posting, where the application happens. Only jobs posted by employers on the platform accept in-app applications.

Which resume does the employer see?

The seeker's latest uploaded resume at the moment they applied. It is linked to the application, so uploading a new resume later does not change what that employer sees. The employer can view the extracted skills, the AI career fit and download the PDF.

How do job recommendations for a seeker work?

Every live job is scored against the skills in the seeker's latest resume: the share of the job's required skills they have, plus a bonus when the job title matches their predicted career. The best 10 appear on the dashboard and in the Recommended tab.

How does the external job feed work?

An admin enters a keyword and limit on the External Job Feed page. The AI service reads the public RSS feeds (and Adzuna if keys are configured), removes duplicates, and Laravel saves them as approved listings. Running it again updates existing ones instead of duplicating them.

Security and data
How is authentication handled?

JSON Web Tokens. Login returns a signed token that the browser sends on every request. The server verifies the signature, so it doesn't need sessions. Passwords are stored as bcrypt hashes.

What stops a normal user from calling admin endpoints?

Every admin controller method checks the is_admin flag on the server and returns 403. Hiding the admin menu in React is only cosmetic.

What happens when an admin deactivates someone who is logged in?

Their very next request is rejected with 401 by the authentication middleware and the frontend sends them to the login page, where they get a "deactivated" message.

Where are the uploaded resumes stored? Are they public?

In storage/app/private/resumes on the Laravel server, which is not web accessible. They can only be downloaded through authenticated endpoints by the owner or by an employer the seeker applied to.

Can a user delete their data?

Seekers can delete any analysis, which removes the stored PDF too. Admins can delete whole accounts; related resumes, applications and saved jobs are removed by cascading foreign keys.

Is there protection against abuse?

Resume upload and analysis are rate limited to 10 requests per minute per user and login/registration to 10 per minute per IP. Files are limited to 2 MB PDFs, every form and filter is validated server side (bad input returns 422, never a crash), search terms are escaped so % and _ are treated literally, and Eloquent's parameter binding prevents SQL injection.

Running and extending
How do I run it locally?

On macOS or Linux, ./setup.sh then ./start.sh. On Windows follow the manual steps in the Running it section. Then open http://localhost:5173.

How do I create the first admin?

php artisan admin:create you@example.com --password=YourPass1 in backend/laravel-api, or run php artisan db:seed for the demo admin.

PDF upload fails with "required binary was not found". Why?

poppler's pdftotext is not installed or not on PATH. Install poppler, or on Windows set PDFTOTEXT_PATH in backend/laravel-api/.env to the full path of pdftotext.exe.

How do I add a new career or skill?

Add the skill to SKILLS_DATABASE (and any aliases), add the career with six core skills to CAREER_MAPPING, add its courses and interview questions, regenerate or extend the curated dataset, retrain, and restart. A test checks that every career the model knows has courses and questions.

How would this be deployed to production?

Build the React app (npm run build) and serve it as static files; run Laravel behind Nginx with PHP-FPM and a real database (MySQL or PostgreSQL); run the AI service with uvicorn behind the same proxy but only reachable from Laravel; set VITE_API_URL, APP_URL and AI_SERVICE_URL; use HTTPS.

How is the project tested?

72 automated tests: 59 Laravel feature tests covering every use case and rule, and 13 AI service tests covering analysis, skill extraction, ranking maths and knowledge base coverage. The frontend passes ESLint and a production build.
